# 0001. Stack and architecture for the Book Worm backend

**Date**: 2026-10-07
**Status**: In Progress

## Summary

This spec picks the building blocks for the Book Worm backend: a single Spring Boot 3.5 app on Java 17, Maven, and PostgreSQL, organised in layers (controller, service, repository). Database changes run through Flyway (versioned SQL scripts), tests run on an in memory H2 database because Docker is not installed, and login tokens (JWT) will use Spring Security's built in JWT support. Database passwords come only from environment variables or a local file that git ignores. ## Decision

**Chosen option**: Option 1: Layered Spring Boot 3.5 monolith, Flyway, H2 tests, Spring Security resource server JWT.

One deployable Spring Boot 3.5.16 app (Java 17, Maven, PostgreSQL 16) with package by layer structure, Flyway migrations, `ddl-auto=validate`, H2 (PostgreSQL mode) for tests, and HS256 JWT through `spring-boot-starter-oauth2-resource-server` plus BCrypt when feature 5 is built.

## Consequences

**Positive**:
- One jar, one database, one command to run; easy for a reviewer on Windows.
- Schema is versioned SQL, so the DB rows a reviewer checks match a file in the repo.
- Tests need nothing but the JDK (no Docker, no running PostgreSQL).

**Negative / tradeoffs**:
- H2 is not PostgreSQL: SQL that differs between them (some types, functions, `ILIKE`, JSON) can pass tests and fail on the real DB, or the reverse. Migrations must stay portable.
- Spring Boot 3.5 open source support ended 2026-06-30. No more free patch releases; acceptable for a capstone, not for a long lived product.
- Hand written mappers and controllers mean more boilerplate than code generation.
- HS256 with no refresh token: a stolen token is valid for up to 60 minutes and users log in again after expiry.

**Neutral**:
- The user must create the `bookworm_app` role and `bookworm` database and set `DB_USERNAME` / `DB_PASSWORD` before `mvn spring-boot:run` (the run kit, feature 14, documents this for reviewers). On Windows, `setx` only reaches newly opened terminals.
- `psql` is not on PATH on this machine; it lives in `C:\Program Files\PostgreSQL\16\bin`.
